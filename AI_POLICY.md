# AI policy

Ovra is an IDE for working with AI agents, and it is built that way. This page
explains how the maintainers use agents and what we ask from contributors who
use AI tools.

## How Ovra itself is built

Most of Ovra's code, tests and documentation are written by Claude agents
running Claude Code, several in parallel, each in its own git worktree. The
maintainer sets the tasks, decides the architecture, reviews results and is
responsible for everything that lands on `main`. Agent commits are authored by
Claude and carry a `Co-Authored-By: Claude …` trailer. Changes the maintainer
reviewed line by line also carry a `Reviewed-by:` trailer. Security-sensitive
code (sandbox, network proxy, secrets, permissions, CSP) is reviewed by a
separate reviewer agent with a fresh context, not by the agent that wrote it;
the maintainer decides every change that weakens security.

The process is in the open:

- [`CLAUDE.md`](CLAUDE.md): the rules every agent follows.
- [`docs/adr/`](docs/adr/): architecture decisions, made by the maintainer.
- [`.claude/agents/`](.claude/agents/): the agent roles (implementer,
  reviewer, test writer, UX persona).
- [`docs/ux-reviews/`](docs/ux-reviews/): UX reviews by persona agents that
  use the real app.

The guard rails are automated: every change must pass formatting, clippy,
unit and end-to-end tests with time budgets, dependency license checks and
architecture rules (`just test && just e2e && just lint`).

The maintainer's agents are covered by this section, not by the rules below.

## If you contribute with AI tools

You are welcome to use AI tools. We ask the same things most projects ask:

1. **Disclose it.** Say in the pull request which tools you used and for what,
   for example "Claude Code wrote the first draft; I rewrote the tests". The
   PR template has a field for this.
2. **Understand every line.** You must be able to explain the change and
   answer review questions yourself. "The AI did it" is not an answer.
3. **No autonomous agents.** Agents must not open issues, pull requests or
   comments in this repository without a human reading and sending them.
4. **Write to us yourself.** Issue reports, PR descriptions and replies should
   be your own words. Quoting AI output is fine when marked as such.
5. **Agree first, then generate.** Large AI-written changes are accepted only
   for issues a maintainer has already accepted.
6. **Tests are required**, as for every behaviour change.
7. **No AI-generated images, audio or video** in the repository.

Maintainers may close contributions that break these rules without a detailed
review.
